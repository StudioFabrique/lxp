Définition. Le couplage décrit à quel point un module dépend des détails d’un autre pour fonctionner. L’objectif est un couplage faible aux détails, fort aux contrats stables.

Formes de couplage à connaître.

  • Structurel : dépendances directes à des classes ou schémas.
  • Temporel : nécessité que deux modules soient disponibles en même temps (appels synchrones).
  • Données : partage de tables, structures, messages non versionnés.
  • Comportemental : présumer l’ordre ou la fréquence d’appels.

Pourquoi c’est risqué.

  • Propage les pannes (effet cascade).
  • Ralentit l’évolution (changement coordonné entre équipes).
  • Augmente la difficulté de test (mocks fragiles, environnements lourds).

Réduire le couplage sans isoler inutilement.

  • Contrats explicites : interfaces, DTO, schémas d’événements, versionnés.
  • Adapters (Ports-Adapters / Hexagonal) pour dépendre de ports abstraits.
  • Asynchrone quand le temps réel n’est pas indispensable (évite le couplage temporel).
  • Anti-corruption layer pour protéger un domaine d’un système externe “bruyant”.
  • Stabilité des interfaces : évoluer de manière additive et déprécier proprement.
