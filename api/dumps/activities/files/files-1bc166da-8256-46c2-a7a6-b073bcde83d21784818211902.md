## Infos Générales
**Titre du projet** : Application de prise de notes en Node JS et Express JS  (V1).
**Client** : Formateur de développement web (cours intermédiaire en Node.js)  
**Objectif** : Permettre aux utilisateurs de créer, consulter, modifier et supprimer des notes de manière simple et efficace avec une interface intuitive et des fonctionnalités de gestion basiques. L’application ne disposera pas d’une base de données (en première version) et les notes seront stockées en mémoire (local Storage).

---
## 1. Présentation du Projet
### 1.1 Contexte
Cette application est développée dans le cadre d’un cours sur Node.js et Express.js, destiné à enseigner la création d’API RESTful et la gestion d’un projet web sans base de données (NoSQL).
### 1.2 Objectif Général
Fournir une application qui permet de prendre des notes. Les notes peuvent être temporaires dans la première version (elles disparaissent lorsque le serveur redémarre), mais elles doivent pouvoir être facilement créées, visualisées, modifiées et supprimées au sein d’une même session.
### 1.3 Utilisateurs
L’application est destinée à tout utilisateur souhaitant noter rapidement des informations et y accéder via une interface API simple.

## 2. Spécifications Fonctionnelles

### 2.1 Fonctionnalités de Base
1. **Créer une Note**
    - Endpoint : `POST api/v1/notes`
    - Description : Permet à l’utilisateur de créer une note en spécifiant un titre et un contenu.
    - Données : `{ title: "Titre de la note - String", content: "Contenu de la note - String", date: "date de la note", favoris: "boolean", tag: "mots-clés relative à la note - Array" }`
    - Retour : La note créée avec un identifiant unique et l’horodatage de création.
2. **Lire toutes les Notes**
    - Endpoint : `GET api/v1/notes`
    - Description : Affiche une liste de toutes les notes enregistrées dans la session.
    - Retour : Une liste d’objets notes `{ id, title, content, createdAt, updatedAt }`.
3. **Lire une Note Spécifique**
    - Endpoint : `GET api/v1/notes/:id`
    - Description : Affiche le contenu d’une note en fonction de son identifiant.
    - Retour : Détails de la note `{ id, title, content, createdAt }`.
4. **Mettre à Jour une Note**
    - Endpoint : `PUT api/v1/notes/:id`
    - Description : Permet de mettre à jour le titre ou le contenu d’une note existante.
    - Données : `{ title: "Nouveau Titre", content: "Nouveau Contenu" }`
    - Retour : La note mise à jour avec l’horodatage de mise à jour.
5. **Supprimer une Note**
    - Endpoint : `DELETE api/v1/notes/:id`
    - Description : Supprime une note en fonction de son identifiant.
    - Retour : Un message de confirmation de suppression.

### 2.2 Spécifications Non Fonctionnelles
1. **Performance**
    - L’application doit répondre en moins de 300 ms pour chaque requête en moyenne, dans des conditions normales d’utilisation.
2. **Accessibilité**
    - L’API doit être accessible en HTTP et lisible via des outils comme Postman ou des interfaces front-end simples.
3. **Maintenabilité**
    - Le code doit être organisé pour être facilement compréhensible et modifiable (architecture en couches : routes, contrôleurs, logique métier).

## 4. Spécifications Techniques
### 4.1 Environnement et Langages
- **Backend** : Node.js, Express.js
- **Format de données** : JSON pour toutes les interactions API
- **In-Memory Storage** : Utiliser des structures de données en mémoire (tableau d’objets) pour stocker les notes temporairement pour V1 ( NoSQL pour V2)
### 4.2 Architecture
- **Structure MVC (Model-View-Controller)** simplifiée :
    - **Routes** : Définit les routes d'API pour gérer les notes.
    - **Contrôleurs** : Logique métier pour les fonctionnalités CRUD.
    - **Stockage** : Tableau ou objet en mémoire pour stocker les notes.
